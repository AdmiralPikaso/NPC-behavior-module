# zero — модуль поведения NPC (Godot 4.7 .NET, C#)

## Запуск
1. Открыть папку `zero` в Godot 4.7.2 .NET (`Godot_v4.7.2-stable_mono_win64.exe` → Импорт → `project.godot`).
2. Нажать **F5** (главная сцена — `scenes/test/TestLevel.tscn`). Если Godot просит собрать проект — кнопка «Собрать» (молоток) справа сверху.

Управление: **WASD** — ходьба, **Shift** — бег, **Alt** — спринт, **C** или **Ctrl** — присед, **Space** — прыжок,
**ПКМ** (держать) — прицел (персонаж смотрит туда же, куда камера, и ходит боком), **ЛКМ** — огненный шар,
мышь — камера, **Esc** — отпустить курсор (щелчок — захватить снова). Игрок и NPC используют один и тот же
слой действий `ActorBody`: игрок отличается только источником намерений (ввод вместо ИИ).

## Пересборка персонажа
Если нужно добавить анимации — дописать их в `CLIPS` в `tools/blender/build_character.py`
(исходник положить в `assets/_source/synty/Animations`) и запустить:
```
"C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe" -b --factory-startup --python tools\blender\build_character.py
```

## Патруль
Точки — дочерние узлы `PatrolRoute` (тип `PatrolPoint`), двигаются мышью. У точки есть время стоянки
и флаг «повернуться по направлению точки». Режим обхода (`Loop`, `PingPong`, `Random`) задаётся у маршрута.
Навигационная сетка запекается автоматически при запуске сцены.

- Synty Studios — ANIMATION Base Locomotion v3 (персонаж Polygon, анимации, текстура T_Polygon_Dummy_01).
- Synty Studios — POLYGON Dark Fantasy (Godot 4.6.2, v1.0.0): окружение арены и персонажи (охотник, скелеты, оружие в руках). Платный пакет, в репозиторий не кладётся

## Атомарные действия (итерация 1)
В тестовой сцене NPC **Mage** (режим `Showcase`) по кругу выполняет все действия по точкам `ShowcaseRoute/S0…S3`:
шаг → бег с прыжком → спринт → присед и шаг в приседе → прыжок на месте → поворот к мишени →
3 огненных шара → стрейф влево и вправо со стрельбой. Мишень — NPC **Dummy** (режим `Idle`).
Текущее действие подписано над головой, начало каждого шага и попадания пишутся в Output (`[бой] …`).
Для записи ролика без игрока: сцена `scenes/test/ShowcaseCapture.tscn` (камера следует за Mage), например
`Godot_v4.7.2-stable_mono_win64_console.exe --path . res://scenes/test/ShowcaseCapture.tscn --write-movie C:/tmp/f.png --fixed-fps 30`.

## Проверка управления без человека (итерация 2)
`scenes/test/PlayerCapture.tscn` проигрывает записанный ввод (`InputScript`: шаги вида `"4.8 tap jump"`,
`"8 mouse 204 -20"`): шаг, бег, спринт, прыжок, присед, поворот камеры, прицел со стрейфом и стрельба.
При выходе из сцены в Output печатается итог `[итог] имя: выстрелы / попадания / урон…` — его же
будем использовать для сравнения тактик. Стрельба игрока требует захваченного курсора, поэтому
сцену нужно запускать с окном (например, с `--write-movie`), а не `--headless`.

## Арена и тактики (итерации 4–5)
- `scenes/arena/Arena.tscn` — играть самому против отряда из 4 NPC: **1–5** — тактика (штурм, прикрытие и
  перебежки, обход с фланга, оборона из укрытий, **5** — «Роли» по схеме Uncharted 4: давящие, засадник,
  защитник сильной позиции, право огня по приоритету), **R** — новый раунд, **E** — тихое
  устранение вплотную (со спины или пока враг не в тревоге). Чтобы играть в стелс-режиме, у корня сцены
  включить `Stealth` (ночь, патрули, зрение/слух/подозрение).
- `scenes/arena/ArenaSquad8.tscn` — та же арена против 8 NPC, старт с тактики «Роли» (клавиши те же): открыть
  сцену в редакторе и нажать **F6**. Здоровье игрока — поле `MaxHealth` у узла `Player` этой сцены (по умолчанию 100).
- Ручная игра на арене идёт в «игровом профиле»: урон 25 (враг падает с четырёх попаданий), выстрел раз в 0,55 с,
  магазин на 8 выстрелов и перезарядка 1,6 с (сама, когда магазин пуст; **F** — вручную), здоровье восстанавливается
  через 5 с без урона (20 в секунду). **F1** — переключить на профиль замеров (исходные урон 20 и 0,8 с, без магазина
  и восстановления), **G** — наблюдатель (урон по игроку не проходит, враги ведут себя как обычно),
  **[ / ]** — скорость времени 0,5× / 1× / 2×, **H** — скрыть или показать текст арены (HP игрока и подписи над
  врагами видны всегда). Во время перезарядки вокруг прицела заполняется кольцо, рядом остаток магазина (пустой —
  красный); ниже 60% здоровья картинка теряет цвет и темнеет по краям. Значения — группа «Игровой профиль» у корня
  сцены; прогоны с ботом их не используют.
- `ArenaExperiment*.tscn` — автоматические прогоны с ботом-игроком, итог в `docs/results`.
  Запуск без окна: `Godot_v4.7.2-stable_mono_win64_console.exe --headless --path . res://scenes/arena/ArenaExperiment.tscn --fixed-fps 60`.
- Код: `src/Ai/Tactics` (отряд, тактики, оценка позиций), `src/Ai/Stealth` (восприятие, подозрение,
  автомат тревоги `StealthBrain`), `src/Arena`, `src/Player/PlayerBot.cs`.
- Подпись над NPC: состояние/роль и подозрение; цвет — уровень тревоги (голубой — спокоен, жёлтый —
  подозревает, оранжевый — ищет, красный — тревога).

## Декор арены (тёмное фэнтези)
Арена и тестовая сцена оформлены как заброшенное кладбище у руин собора (Synty POLYGON Dark Fantasy).
Декор — **только картинка** поверх серых коробок: физика, навмеш, лучи зрения, точки укрытий и свет
по-прежнему берутся из коробок в `NavigationRegion3D` и из `Torch1..6`, итоги прогонов ботов с декором и без
совпадают.
- `scenes/arena/decor/ArenaDecor.tscn` подключён в `Arena.tscn` (и во все наследники) одним узлом `ArenaDecor`
  вне `NavigationRegion3D`; `scenes/test/decor/TestLevelDecor.tscn` — так же в `TestLevel.tscn`.
- Скрипт `src/Arena/ArenaDecor.cs` при запуске сразу удаляет у декора все физические тела (у префабов Synty
  они свои) и скрывает меши серых коробок. Чтобы увидеть коробки вместе с декором (проверить совпадение
  габаритов), у узла `ArenaDecor` выключить **HideGreybox**.
- Группа `Cover/<имя>` в декор-сцене относится к коробке с тем же именем: низкие укрытия 3×1.2×0.6 — кирпичные
  стенки со столбиками или скамьи собора, блоки 2×2×2 — гробницы, постаменты со статуями, штабели ящиков,
  стены 6×2.5×0.5 — кирпичные пролёты со столбами. Префабы вписаны в габариты коробки по AABB (неравномерный
  масштаб), выше коробки торчат только статуи на постаментах (выше 2 м, над головами). Бордюр — кладбищенская
  ограда, под каждым `Torch*` — столб с жаровней (свет не менялся). Север арены — неф собора (плитка),
  юг — кладбище; за оградой фон: руины собора, склепы, надгробия, мёртвые деревья, холмы, луна.
- Сцены собираются скриптом, руками их править не нужно (правки пропадут при пересборке):
  ```
  dotnet build
  Godot_v4.7.2-stable_mono_win64_console.exe --headless --path . -s res://tools/godot/build_arena_decor.gd
  ```
  Свой префаб: в `tools/godot/build_arena_decor.gd` вызвать `_fit(группа, "Props/SM_Prop_…", центр, размер)` —
  вписать в коробку, или `_drop(группа, "…", точка, поворот, масштаб)` — поставить на пол. Если ставите что-то
  на путь ботов, оно должно быть плоским или совпадать с коробкой: коллизии у декора нет.
- Пакет не хранится в git. На новой машине: распаковать `POLYGON_Dark_Fantasy_Godot_4_6_2_v1_0_0.zip` и
  скопировать `polygon-dark-fantasy-01/Assets/Synty` в `zero/assets/Synty` (именно в этот путь: префабы
  ссылаются на `res://assets/Synty/PolygonDarkFantasy/…`), затем открыть проект, чтобы Godot импортировал файлы.
  Импорт даёт ~215 предупреждений «Case mismatch» (в пакете смешаны пути `Assets/` и `assets/`): на Windows
  это не мешает, на системах с регистрозависимой ФС ссылки сломаются.

## Персонажи (тёмное фэнтези)
Игрок — охотник (`SM_Chr_Hunter_Male_01`: шляпа, волосы, плащ, посох в правой руке), враги — скелеты Synty
POLYGON Dark Fantasy. Смена модели — **только картинка**: капсулы, скорости, высота глаз и выстрела, ИИ и
навигация не менялись, итоги прогонов ботов (арена и стелс) с новыми моделями совпадают с прежними до цифры.
- Обе сцены актёров (`Player.tscn`, `NpcAgent.tscn`) берут модель из
  `assets/characters/darkfantasy/DarkFantasyCharacters.glb`. В нём на одном скелете с анимациями лежат все скины,
  меши названы `<Скин>__<меш>`. Скрипт `src/Common/Visual/CharacterSkin.cs` на узле `Visual/Model` показывает
  меши выбранного скина, ставит им материал пакета и вкладывает оружие в кость `Prop_R` (без коллизий).
- Свойства `CharacterSkin`: **Skin** — `AutoSkeleton` (по умолчанию у NPC: вариант по номеру в имени —
  Enemy1 → `Skeleton`, Enemy2 → `SkeletonLightArmor`, Enemy3 → `SkeletonHeavyArmor`, Enemy4 → `SkeletonRanger`,
  дальше по кругу; без номера — по порядку в сцене), `Mannequin` (прежний жёлтый манекен), `Hunter` (у игрока),
  `Skeleton…`; **Weapon** — `Auto` (охотнику посох, скелетам меч / топор / булава / арбалет), `None` или конкретное.
  Скрипт работает и в редакторе (`[Tool]`), выбранный скин видно сразу. Старый `PolygonCharacter.glb` не тронут.
- Проверить все скины на всех клипах рядом с капсулой 1.8 м: открыть `tools/godot/SkinGallery.tscn` и нажать F6
  (параметры `clip`, `close`, `yaw_deg` у корня).

**Как устроено и почему так.** Скелет Characters.fbx совпадает с анимационным по именам и иерархии
(отличаются только пальцы: `Finger_01_L/_R` против `Finger_01/Finger_01_1`, нет `Prop_L/R`), длины костей равны,
но поза покоя другая (T-поза против A-позы), а локальные оси костей повёрнуты (у позвоночника и ног на ~90°).
Поэтому ни подмена меша, ни копирование матриц костей не подходят: меш перепривязывается в Blender. Скелет
Dark Fantasy ставится в позу покоя анимационного скелета по суставам (кость доворачивается так, чтобы
направление «сустав → дочерний сустав» совпало, кисть — ещё и по большому пальцу), меш запекается в этой
позе и привязывается к общему скелету с анимациями, кости пальцев переименовываются. Насадки (шляпы, шлемы,
плащи) в пакете есть только как меши Godot, поэтому их сначала выгружает Godot (в мировых координатах, как они
стоят в префабах), а Blender жёстко привязывает их к кости `Head` / `Spine_03`.

**Сборка** (нужен пакет в `assets/Synty`, см. «Декор арены»; результат не в git — собран из платных моделей):
```
dotnet build
Godot_v4.7.2-stable_mono_win64_console.exe --headless --path . -s res://tools/godot/export_character_parts.gd
"C:\Program Files (x86)\Steam\steamapps\common\Blender\blender.exe" -b --factory-startup --python tools\blender\build_character.py -- --darkfantasy
Godot_v4.7.2-stable_mono_win64_console.exe --headless --path . --import
```
Первый шаг пишет `assets/characters/darkfantasy/parts/` (`attachments.glb`, `manifest.json`, папка с `.gdignore`),
второй — `DarkFantasyCharacters.glb` (в логе строки `check …` — совпадение координат Godot и Blender, `кисть …` —
доворот кистей). Без ключа `--darkfantasy` скрипт, как и раньше, собирает только `PolygonCharacter.glb`.

**Добавить скин:** вписать `"ИмяСкина": "SM_Chr_…"` (префаб из `Prefabs/Characters`) в `SKINS` в
`tools/godot/export_character_parts.gd`, добавить `ИмяСкина` в `SkinKind` в `CharacterSkin.cs` (и в `SKINS`
галереи), пересобрать тремя командами выше. Насадки и состав мешей берутся из префаба автоматически.
Хват оружия задан в `CharacterSkin.WeaponMesh` (оси `Prop_R` во время клипов: X — вверх вдоль руки, Z — вперёд).
